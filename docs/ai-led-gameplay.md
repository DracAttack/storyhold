# AI-Led Gameplay

Live campaign turns use the same AI-and-rules workflow for fresh RPG adventures
and worlds created from manuscripts. Their starting knowledge differs; their
turn loop does not require the manuscript-intake model sequence.

## Turn Responsibilities

1. Retrieve relevant saved facts, canonical identities and aliases, graph links,
   campaign history, and source passages using existing database and deterministic
   ranking. Source scope, character visibility, and frozen campaign canon remain
   enforced.
2. The Director proposes structured world changes and classifies them as reality,
   character knowledge, beliefs, or claims. It works within committed RPG outcomes,
   time, pacing, and allowed resource changes.
3. Code validates those changes. The Narrator writes from the accepted public
   decision. Only accepted state changes enter the campaign transaction, linked
   to the originating turn and state version.
4. Manual testing pauses at the AI boundary. An operator supplies the Director
   and Narrator responses through the same structured validators, without paid
   generation or credit charges.

## No Automatic Specialist Pass Per Turn

Opening a play page and submitting a turn do not invoke GLiNER, NLI, local Qwen,
browser WebGPU assistance, BGE reranking, query-embedding models, or per-turn
embedding backfills. Global browser-acceleration settings no longer redirect a
new campaign turn to a browser model. Existing saved browser-narration proposals
remain recoverable; they are not new routing defaults.

The API reports the execution policy. Client-submitted extraction hints or
browser-narration preferences cannot override the server's live-turn route.

This does not mean a semantic model checked the prose. Private diagnostics mark
specialist verification as not run; they must not represent it as a passed check.
Deterministic identity, canon, causality, progression, visibility, RPG, duplicate
submission, and transaction checks remain in force. These checks cannot prove
that every sentence generated by an AI is semantically correct.

## What Remains Intact

- Manuscript intake, source text, existing embeddings/indexes, dossier review,
  and local model installations.
- Canonical records, relationship/history data, imported-canon boundaries,
  game mechanics, immutable committed outcomes, and saved turns.
- Existing provider routing for Director/Narrator and manual test mode.

No world data is migrated or deleted by this routing change.

## Question Length

New questions use a direct-answer instruction: a simple question normally needs
1-3 sentences, with no minimum word count. Complex questions and explicit requests
for detail can receive fuller answers. Extra scene recap or invented action must
not be used to fill space. The public resolution and its consequences still bind
the Narrator.

Action and author-event narration retains the existing concise/balanced/expansive
targets and output-token ceilings. Question token ceilings also retain headroom
for a genuinely detailed answer; no response is cut off at a word-count limit.
This shared request builder applies to paid narration and manual testing.

New manual packets freeze an intent-aware narration policy. Older unversioned
packets reconstruct their original legacy instructions, including an already
prepared Narrator request. Fingerprint checks and exactly-once completion remain
in force. Existing published turns are not rewritten.

## Retrieval Tradeoff

Saved evidence remains retrievable, but model-powered semantic reranking and
fresh query embeddings are no longer automatic prerequisites for a live turn.
Lexical, alias, identity, graph, and history retrieval can miss connections with
very different wording. Long-campaign tests should measure that gap before
introducing a targeted, explicit semantic-retrieval path. Do not silently restore
the entire intake stack to every turn as a shortcut.

existing orderly lifecycle while preserving its local-intake environment. Do not
force-stop the database process or replay an already committed gameplay turn.
