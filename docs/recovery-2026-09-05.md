## Incident and Recovery

An offline reset opened the embedded vault while an older local server was still running. The old server's later shutdown left the control file pointing to an invalid earlier checkpoint. The process check used before maintenance was insufficient.

After the old server was stopped and its processes exited, recovery proceeded only on a copy. The preserved current WAL contained a valid PostgreSQL 18 shutdown checkpoint at `1/8678C828`, dated September 5 at 06:10:05 UTC. Validation checked matching system identity, timeline, page layout, control checksum, checkpoint checksum, and 32 linked preceding records. The copy's checkpoint reference, checkpoint payload, timestamp, and checksum were repaired; the original damaged vault was not modified further.

The repaired copy was used for read-only logical export with the version-matched official PGlite pg_dump tool. Its data was restored into a newly initialized database. Every row-content fingerprint and row count matched across all 76 original tables, and restored database constraints validated. No older backup was used. These checks establish export/rebuild fidelity; they are not a claim of comparison against an unavailable pre-incident snapshot.

The requested three-world deletion was repeated on the clean vault and verified after closing and reopening it. Current schema migration then completed, producing 101 tables. Live checks confirmed owner login, 5,000 credits, an empty world list, the enabled private manual-storyteller queue, unauthorized queue access rejected with HTTP 401, and refusal of a second vault owner. Multiple orderly stop/start checks passed, and the signed-in browser displayed the empty library.

## Prevention

- `vaultOwnership.ts` provides a shared exclusive ownership lease independent of HTTP readiness. Persistent-vault maintenance must acquire it before PGlite and release it only after `db.close()` succeeds.
- Startup migration errors now close the database before releasing ownership.
- A migration-order regression was fixed: the campaign parent column is created before the world-card view uses it.
- Six ownership tests and the legacy-schema startup regression passed.
- Older standalone maintenance scripts must not open the active vault without adopting the shared lease. HTTP silence alone is never sufficient evidence that it is safe to open another writer.
