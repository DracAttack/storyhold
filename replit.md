# Workspace

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.
BrainHook is a smart-clickbait magazine: an Express 5 API (`artifacts/api-server`) that
auto-generates articles + hero images and a React/Vite reader site (`artifacts/site`)
with prod-only Node SSR for SEO meta. Postgres + Drizzle; contract-first OpenAPI/Orval.

## Artifacts

- **site** (`artifacts/site`) — reader-facing magazine. React + Vite SPA; in **production** a Node server (`server/index.ts`) injects per-route SEO meta (dev stays pure Vite). Deployed.
- **api-server** (`artifacts/api-server`) — Express 5 API: content pipeline, admin, email, cron tick. Deployed.
- **mockup-sandbox** (`artifacts/mockup-sandbox`) — dev-only canvas/component preview tooling (`kind = "design"`). NOT deployed (no `[services.production]`) and excluded from root `typecheck`/`build` via `--filter "!@workspace/mockup-sandbox"`.
- **bpdisms** (`artifacts/bpdisms` + `artifacts/bpdisms-api`) — "BPD-isms Post Queue": standalone meme scheduler posting to a Facebook page via Zernio, imported from a separate app and firewalled from BrainHook (own React/Vite UI at `/bpdisms/`, own Express API at `/bpdisms/api`, namespaced `bpdisms_*` tables, `BPDISMS_ZERNIO_API_KEY` secret — never reuses the main app's `ZERNIO_API_KEY`). Only main-site touchpoint: an admin-sidebar anchor to `/bpdisms/`. **Gated behind the shared BrainHook admin session** — bpdisms has no login of its own; it validates the same `cm.sid` cookie (same `SESSION_SECRET` + Postgres `user_sessions` store as api-server, mirrored in `bpdisms-api/src/lib/auth.ts`), so signing in once at `/admin/login` unlocks `/bpdisms/` on the same domain. This is the one intentional exception to "shares only `@workspace/db`": auth also reuses `ADMIN_EMAILS`/`SESSION_SECRET`. The API gates every route except `/healthz` and the two GET image-serving routes (`/storage/public-objects/*` and `/storage/objects/*`) — those must stay public because Zernio/Facebook fetch meme image URLs server-side with no cookie. The web app shows a sign-in prompt (link to `/admin/login`) when `/api/me` returns 401. Both services deploy (web static + API with `/bpdisms/api/healthz` health check). **Live posting requires two explicit env vars** — `BPDISMS_POSTING_ENABLED=true` (hard gate; any instance without this is posting-disabled by default, even if the API key is present) and `BPDISMS_DESTINATION_ID=<zernio-account-id>` (seeds the FB destination on first boot; without it the destination starts null and must be set in Settings UI). This prevents dev/preview/restored instances from silently firing posts to the real page.

## Stack

- **Monorepo**: pnpm workspaces · **Node**: 24 · **TypeScript**: 5.9
- **API**: Express 5 · **DB**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod` · **API codegen**: Orval (from OpenAPI) · **Build**: esbuild (CJS bundle)

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm run storyhold:build && pnpm run storyhold:start` — build and run the complete Storyhold app on Replit (UI + API + embedded persistent database on port 3000)
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks + Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run the API server locally

## Notes

- **Dev vs prod DBs are separate.** Schema changes heal automatically: `ensureRuntimeTables` (in `services/seed.ts`) runs idempotent boot DDL (creates runtime-only tables, `ADD COLUMN IF NOT EXISTS`) so fresh/reset/rolled-back dev DBs stay in sync without manual `push`. Keep these guards in sync with the schema in `lib/db/src/schema` (the source of truth). One-time data fixes run as guarded migrations recorded in the `app_migrations` ledger.

- **Admin auth.** Access is an explicit allowlist — `ADMIN_EMAILS` (comma-separated) + `ADMIN_PASSWORD_HASH`, both **Replit Secrets**. The password field accepts either a bcrypt hash or the plaintext password (auto-detected, value is trimmed). The server refuses to start without both — there is no "any signed-in user is admin" fallback. Add an admin by appending to `ADMIN_EMAILS` and restarting; they sign in with the shared password at `/admin/login`. Same allowlist drives daily digest recipients.

- **AI hero + share images.** Hero images are generated by Gemini (`gemini-3-pro-image-preview`, Nano Banana Pro — billed per generation, ~$0.13+/image) via the Replit Gemini integration (`AI_INTEGRATIONS_GEMINI_*`, auto-provisioned), 16:9 PNGs stored in App Storage. A content/safety refusal (`NoImageDataError`) is **not** retried with a safer prompt (that double/triple-billed the Pro model on exactly the refused articles) — it falls **straight to the branded default share card** (pipeline) or a 422 (admin regen). **There is no picsum/stock fallback anywhere** — on failure or when AI images are disabled, both hero and share image resolve to the **branded default share card** (BrainHook lockup + tagline; master at `artifacts/api-server/assets/default-card.png`). Each article also gets a composed 1200×630 og:image (hero + scrim + logo + title); the homepage share image is `artifacts/site/public/opengraph.jpg`. `@google/genai` must be a direct dep of the API server (esbuild externalizes `@google/*`).

- **Content pipeline.** Authors publish on a **rotating weekly** cadence at a random UTC hour; after each post publishes the author is moved to a new weekday/hour to keep load ~1–2/day. Manual triggers — "Generate draft" (per idea), "Run pipeline now" (all authors), and force-schedule drafts — are **fire-and-forget**, returning `202` immediately and running in unawaited promises guarded by module-level in-process booleans (single-server assumption; a real queue would be needed to scale horizontally). Idea generation auto-pauses per author when their approved-idea bank hits the cap.

- **Scheduling runs via an external cron tick.** Production is **autoscale**, where in-process `node-cron` is unreliable, so all scheduled work is driven by a token-protected `GET /api/cron/tick` pinged by UptimeRobot every 5 min; the in-process cron timers only run in dev (`NODE_ENV !== "production"`). Cross-instance idempotency comes from a `cron_job_runs` ledger (atomic claim per job+period). Token via Secret `CRON_TICK_TOKEN`, passed as `?token=` or `X-Cron-Token` header. Each job still self-gates on its existing rules; the tick only changes the trigger.

- **Email (Resend over SMTP).** All mail (subscriber welcome + weekly newsletter) goes through a provider-agnostic layer that picks **smtp** when `SMTP_HOST` is set, else a **mailbox** fallback that writes HTML files in dev. Connected provider is **Resend** via SMTP secrets (`SMTP_HOST=smtp.resend.com`, `SMTP_PORT=465`, `SMTP_USER=resend`, `SMTP_PASS=<API key>`, `EMAIL_FROM=newsletter@brainhook.net`); domain `brainhook.net` is verified so it delivers to real subscribers. Sends are fire-and-forget and never throw (signup never blocked). Single opt-in. Weekly newsletter blasts Sunday 13:00 UTC (= 6:00 AM Phoenix/MST, Arizona has no DST); schedule (weekday + UTC hour) is editable in Admin → Settings and stored in `site_settings` (prod row must be changed there, code default only seeds fresh DBs). Prod email links need `SITE_BASE_URL=https://brainhook.net` or they fall back to the dev domain.

- **Editorial trust box & references.** Every public article returns `references` (its evidence source graph: role=evidence, non-rejected, deduped by URL, authority-tier-first) and `editorial` metadata — all derived deterministically, **no AI**. Label: `research_synthesis` (evidence packet OR 2+ primary/firsthand/wire sources) → `analysis` (any cited source) → `explainer` (none); `original_reporting`/`commentary` reserved for future manual designation, never auto-claimed. Date line: `factCheckedAt` (verification report) → last source insertion → article `updatedAt` (so topping up sources refreshes the box). Editor of record: Damien Lynn. Site renders the "How this article was produced" box above the prose and a nofollow'd References list after it. Admin → Articles has a synchronous "Strip search-engine links" sweep (removes Google-Scholar/search-results links, keeps anchor text).

- **Author URL slugs.** An author's public URL is `/author/<slug>` and the slug is the stable identity — internal links derive from `article.author.slug`, so renaming the slug re-points every link instantly. Slug is editable in the admin UI; a change validates uniqueness and records a redirect (`author_slug_redirects`), and the prod SSR server emits a **301** from retired aliases. The previously noted `marcus-vance`→"Brenna Vance" stale-slug mismatch is now resolved in prod (slugs match their author names). Remaining cosmetic blemish: three author names have trailing whitespace in the DB ("Brenna Vance ", "Jennifer Marsden ", "Paul Wardell ") — display-only, not a broken slug/URL; trim via the admin editor or a guarded migration if desired.

- **SQL regex in `sql`` template literals — use POSIX classes.** In a JavaScript/TypeScript template literal, backslash-escape shorthands like `\s`, `\d`, `\w` are silently dropped — PostgreSQL sees `s`, `d`, `w` instead of the intended character class. Always use POSIX classes in the literal text portions of `sql`` blocks: `[[:space:]]` for `\s`, `[[:digit:]]` for `\d`, `[[:alnum:]_]` for `\w`, etc. Double-backslash (`\\s`) inside a `${}` interpolation is fine — it produces the correct `\s` string value at runtime. The `lint-sql-regex` validation step (`node scripts/lint-sql-regex.mjs artifacts/api-server/src`) catches this class of bug automatically.
